# Fable 5.1 への相談

失敗原因を絞れない、設計案を比較したい、指摘への見解が割れる場合に読む。Fable 5.1 は読み取り専用の相談役であり、通常レビューと実装は Codex が担う。

## 呼び出し

メインから MCP を直接呼ぶ。調査資料や相談履歴が長く、切り離す効果がある場合だけ `relay_fable_advisor` を起動する。薄い中継だけのためにサブエージェントを増やさない。

既存接続との互換性のため、MCP サーバー名は `claude_fable_reviewer`、ツール名は `review_with_fable` である。ツールが見えない場合は利用可能なツール検索で探す。子から MCP が見えない場合はメインで呼び、エージェントを連鎖させて探さない。

引数は `cwd`（作業ルートの絶対パス）、`prompt`、必要な場合だけ `timeout_ms` である。`prompt` には次を含める。

- 目的・対象・制約・完了条件と、今回決めたい論点。
- 確認済みの事実、再現条件、試した案と結果、未確認の仮説。
- 読むべき設計書・差分・ログのパスと、必要な検証出力。秘密値や認証ファイルの内容は含めない。
- 期待する回答: 根拠付きの仮説、代替案とトレードオフ、反証方法、推奨する次の確認。

ブリッジは Claude Code CLI の `claude-fable-5-1` を明示指定し、`plan` モードと読み取り用ツールで呼ぶ。Codex の `model` 欄に Fable を指定しない。相談結果は決定済み仕様ではなく、メインがコード・仕様・観測結果と照合して採否を決める材料である。

## 継続と失敗

一度の相談で論点をまとめる。追加の相談には新しい証拠か未解決の具体的な問いを渡し、同じ依頼を繰り返さない。継続エージェントを使う場合も、MCP 呼び出し自体はステートレスなので必要な相談履歴を渡す。

未接続・未認証・モデル未提供・タイムアウトは原因を報告し、Fable が回答した扱いにしない。別の Claude モデルへ自動で切り替えない。Codex が解決できる作業は続け、仕様判断が必要な論点だけをユーザーへ戻す。
